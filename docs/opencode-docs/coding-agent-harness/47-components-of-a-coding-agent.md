# Components of a Coding Agent (Harness Engineering)

## Sources

## Ключевой тезис

Харнесс (обвязка вокруг модели) зачастую важнее самой модели. Одна и та же модель в CLI с хорошим харнессом ощущается значительно мощнее, чем в веб-чате. Прогресс в практических LLM-системах сейчас идёт не столько через улучшение моделей, сколько через то, как мы их используем.

## Разграничение понятий

```
LLM          — сырая модель предсказания следующего токена
Reasoning-   — LLM, обученная тратить больше compute на
  LLM          промежуточные рассуждения и самопроверку
Агент        — цикл, использующий модель + инструменты + память
Агентный     — программный каркас: контекст, инструменты,
  харнесс      промпты, состояние, поток управления
Кодинг-      — харнесс, специализированный для разработки ПО
  харнесс
```

## 6 компонентов кодинг-харнесса

### 1. Живой контекст репозитория (WorkspaceContext)

Агент заранее собирает «стабильные факты»:
- Git-репозиторий: ветка, статус, последние коммиты
- AGENTS.md / README — инструкции, команды для тестов
- Корневая папка и структура проекта

Превращает «исправь тесты» в осмысленное действие — агент знает, какую команду запустить и где искать.

```
Агентный харнесс → Сбор фактов → Сводка рабочего пространства → Промпт
```

### 2. Структура промпта и кэш (Prompt Shape + Cache Reuse)

Промпт делится на две части:

| Часть | Что содержит | Частота изменений |
|-------|-------------|-------------------|
| **Стабильный префикс** | Правила агента, описания инструментов, сводка workspace | Почти никогда |
| **Состояние сессии** | Последний запрос, недавняя история, краткосрочная память | Каждый шаг |

Умные рантаймы кэшируют KV-кэш стабильного префикса и не пересобирают его с нуля. На практике это даёт огромный прирост скорости и экономии токенов.

```
Стабильный префикс (кэшируется) + Состояние сессии (обновляется) → Промпт → LLM
```

### 3. Инструменты: структура, валидация, разрешения (Structured Tools)

Главное отличие от чата: модель *реально* выполняет команды и получает результат, а не просто предлагает текст.

**Процесс:**
```
Модель → структурированное действие
  → Харнесс валидирует: известный инструмент? корректные аргументы? путь внутри workspace?
  → Подтверждение пользователя (если нужно)
  → Выполнение
  → Результат (ограниченный по размеру) → обратно в цикл
```

**Типичные инструменты кодинг-харнесса:** список файлов, чтение файла, поиск по коду, grep, shell-команда, запись/редактирование файла.

### 4. Борьба с раздуванием контекста (Context Reduction / Compaction)

Кодинг-агенты страдают от раздувания контекста сильнее обычных чатов — из-за повторных чтений файлов, объёмных выводов инструментов, логов.

**Стратегии сжатия (компактизации):**

```
Большие выводы → обрезка (clipping)
Старые чтения  → дедупликация
История диалога → суммаризация (старые шаги агрессивнее, свежие — детально)
Всё вместе     → в промпт
```

Ключевой принцип: последние события важнее — они сжимаются меньше. Старые — агрессивно суммаризируются.

### 5. Структурированная память сессии (Session Memory)

Два уровня хранения:

```
Полный транскрипт (JSON на диске)
  └── Все запросы, ответы LLM, выводы инструментов
  └── Позволяет возобновить сессию после закрытия

Рабочая память (дистиллированное состояние)
  └── Текущая задача, ключевые файлы, последние заметки
  └── Явно обновляется между шагами
```

Полный транскрипт — для восстановления. Рабочая память — для непрерывности задачи. Компактный транскрипт (сжатая история для промпта) — третья сущность, между ними.

### 6. Делегирование и bounded subagents

Субагент позволяет распараллелить подзадачи, не засоряя контекст основного цикла.

**Ключевая проблема — bounds:** субагент должен наследовать достаточно контекста, чтобы быть полезным, но не больше. Типичные ограничения:
- Режим read-only
- Ограничение на глубину рекурсии
- Ограничение на количество шагов

```
Основной агент → задача
  └── Субагент (read-only, max 5 шагов) → «найди определение символа X»
  └── Результат → обратно основному агенту
```

## Relevance to OpenCode

Эта статья — фундаментальная база harness engineering. Все 6 компонентов напрямую применимы к OpenCode:

1. **WorkspaceContext** — OpenCode читает AGENTS.md, `.opencode/`, `instructions` array
2. **Prompt Cache** — OpenCode использует prompt caching, стабильный префикс
3. **Tools** — OpenCode имеет свою систему инструментов с валидацией путей и permissions
4. **Context Reduction** — OpenCode управляет контекстом, хотя механизмы могут отличаться
5. **Session Memory** — OpenCode хранит историю, поддерживает возобновление сессий
6. **Subagents** — OpenCode поддерживает агентов через `task` инструмент

Mini Coding Agent от Raschka — полезный reference для понимания, как устроены эти компоненты «под капотом» в минималистичной форме.

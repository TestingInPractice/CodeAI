## AGENTS.md — общий стандарт

AGENTS.md — это открытый формат, который поддерживается большинством современных кодинг-агентов: Cursor, Gemini, OpenCode, Codex и другими. По заявлениям на сайте, его поддерживает «какое-то нереальное количество агентов».

На практике каждый агент обрабатывает этот файл по-своему, поэтому стоит читать документацию по поддержке AGENTS.md конкретно в вашем инструменте.

## Codex (OpenAI)

Правила загрузки контекста в Codex достаточно обширны:

1. **Домашняя директория** — Codex заходит в `~/.codex/` и ищет:
   - `AGENTS.md`
   - `AGENTS_OVERRIDE.md`

2. **Корень проекта** — `AGENTS.md` в корне репозитория. Рекомендуется пушить его в общий репозиторий, чтобы файл был один на проект и разработчики могли делить его друг с другом.

3. **Локальные директории** — `AGENTS.md` и `AGENTS_OVERRIDE.md` могут лежать в любой поддиректории проекта.

### Правила конкатенации

- Когда Codex обращается к файлам, лежащим в определённой директории, он собирает все `AGENTS.md` по пути от корня до целевой директории.
- Файлы конкатенируются в один большой промт вместе с системным промтом.
- Если на одном уровне лежат и `AGENTS_OVERRIDE.md`, и `AGENTS.md` — берётся только `OVERRIDE`, если он не пустой.
- Если `OVERRIDE` пустой — он пропускается, ищется `AGENTS.md`.
- Все файлы склеиваются в один большой промт — никаких ленивых импортов или подгрузок по требованию.

### AGENTS_OVERRIDE.md

`AGENTS.md` пушится в репозиторий и одинаков для всех разработчиков. Если вам нужны локальные правила, которые отличаются от командных:

1. Создайте `AGENTS_OVERRIDE.md` рядом с `AGENTS.md`
2. Добавьте `AGENTS_OVERRIDE.md` в `.gitignore`
3. Codex возьмёт ваш override вместо общего файла

## Claude Code (Anthropic)

Anthropic пошли по другому пути, и это одна из причин, почему многие так любят Claude Code.

### Ключевые отличия от Codex

- Если в проекте уже есть `AGENTS.md`, нет смысла создавать его копию для Claude — можно использовать те возможности, которые предоставила Anthropic.
- **Ленивая подгрузка файлов** — вы добавляете в `CLAUDE.md` ссылку на файл через `@`, и его содержимое подставляется в контекст только когда это нужно.

### Формат ссылок

```markdown
@полный-путь/к/файлу.md
```

Таким образом, файл подставляется в место ссылки при передаче промта Claude. Дальше вы можете дописать контекст, специфичный для Claude Code.

### CLAUDE.md vs AGENTS.md

Claude читает оба файла — `CLAUDE.md` не заменяет `AGENTS.md`. Иерархия загрузки:

1. Домашняя директория (`~/.claude/`)
2. Корень проекта
3. Специфичные директории с дополнительным контекстом

### CLAUDE_LOCAL.md

Аналог `AGENTS_OVERRIDE.md` для Claude. Добавляется в `.gitignore`, не пушится в репозиторий. Пример использования — «лаконичный режим» (окультуренный системный промт).

### Claude Rules (глобальные и проектные)

Дополнительная возможность для экономии токенов — `CLAUDE.RULES`:

- Лежат в `~/.claude/rules/` (глобально) или `./.claude/rules/` (в проекте)
- Почти обычные `.md`-файлы с frontmatter (YAML)
- В frontmatter указываются **глобы/пути**, по которым правило должно срабатывать

**Пример:**

```yaml
---
paths:
  - "**/*.sql"
  - "**/*.java"
---
```

Это правило сработает для всех SQL и Java-файлов. Другое правило может срабатывать только для файлов по конкретному пути с определённым расширением.

Claude подтягивает эти правила автоматически, когда сталкивается с файлами, подходящими под регулярные выражения. Это позволяет держать `CLAUDE.md` более стройным, оставляя специфику в отдельных rule-файлах.

## OpenCode

В официальной документации OpenCode чётко прописано: если в проекте есть `CLAUDE.md`, OpenCode отлично его читает, в том числе из домашней директории Claude.

Указание файлов через `@` работает не только с `AGENTS.md`. Если вы хотите, чтобы информация о кодстайле попадала в контекст каждой сессии, достаточно в `CLAUDE.md` добавить ссылку на соответствующий файл — OpenCode автоматически подтянет контекст.

## Cursor

Курсор — агент, который официально поддерживает `AGENTS.md`. Но у Курсора есть свои правила, которые работают по схожему принципу:

- Формат правил — не `.md`, а **`.mdc`**
- Создавать их можно прямо через интерфейс Курсора

---

## Gemini CLI (Google)

Gemini также поддерживает `GEMINI.md`:

- Поддерживает **импорты**, как и `CLAUDE.md` (ссылки на файлы через `@`)
- **НЕ поддерживает** Rules (как в Claude)
- **НЕ поддерживает** локальные версии (`GEMINI_LOCAL.md`, `GEMINI_OVERRIDE.md`)

Иерархия жёстко фиксирована:

1. Базовый `GEMINI.md` для пользователя в домашней директории
2. `GEMINI.md` на уровне проекта
3. `GEMINI.md` на уровне произвольной директории

## Лучшие практики

### Что писать в AGENTS.md

В файле стоит коротко описать:

- О чём проект
- Флоу работы с агентом (Plan → Build и т.д.)
- Базовые принципы

В официальной документации также рекомендуется добавлять:
- Команды для запуска разных активностей
- Инструкции по запуску тестов
- Оформление PR

### Чего НЕ стоит делать

Автор доклада считает **избыточным** добавлять в AGENTS.md:

- Команды запуска (LLM сама догадается, как запустить проект через Maven/Gradle и т.д.)
- Code style конвенции (вынесите в отдельный файл и ссылайтесь при проверке)
- Структуру проекта (агент сам может посмотреть)
- Инструкции по деплою (добавляйте только при необходимости)

### Как экономить токены

- Предоставляйте только ту информацию, ответ на которую агент **не сможет получить сам** либо в одно действие.
- Если вы постоянно добавляете одну и ту же фразу в промт — пора внести её в AGENTS.md.
- Каждый раз, когда добавляете новое правило — **перечитайте файл целиком** и удалите устаревшее.
- Проверяйте, как изменения влияют на работу.

### Ссылки на отдельные файлы

Информацию по кодстайлу, деплою, ревью можно вынести в отдельные файлы внутри проекта и ссылаться на них при составлении промта:

```markdown
При проверке кодстайла используй @docs/codestyle.md
При деплое следуй @docs/deploy.md
```

## Заключение

Несмотря на общий стандарт `AGENTS.md`, каждый агент обрабатывает контекст по-своему. Ключевые рекомендации:

- Выбирайте агента под свои задачи и изучайте его механику работы с контекстом
- Не дублируйте контекст — используйте ссылки (`@`) и переиспользуйте файлы
- Держите `AGENTS.md` / `CLAUDE.md` минималистичным — каждый токен на счету
- Регулярно пересматривайте и чистите файлы
